# Token Widget — 잔여량 위젯 (Claude Code · Codex)

**얼마나 남았는지**만 보여주는 위젯. 배터리 잔량처럼 읽으면 된다.

상단 표시줄에는 서비스 이름 + 배터리 안에 숫자가 항상 떠 있고(기본: **5시간 창**), 창을 열면
한도 창(5시간·주간·월)별로 잔량과 **그 창에서 어느 모델을 얼마나 썼는지**가 보인다.

```text
● Claude
5시간                         76%
━━━━━━━━━━━━━━━━━━━━━━━━━━━──────
4시간 8분 후 충전            21:40
opus 5.5 24%

주간                          51%
━━━━━━━━━━━━━━━━━───────────────
14시간 28분 후 충전      내일 08:00
```

- 창의 막대: 잔량 50% 이상 **초록**, 20~50% **주황**, 20% 미만 **빨강**.
- 상단 표시줄: 맥 메뉴 막대처럼 흰색 단색 `Claude 72% ▭` — 20% 미만일 때만 **빨강**.
- 창은 애플 다크 모드 스타일로 Pillow 가 직접 그린다(둥근 카드·매끈한 막대). 화면 배율에 맞춰 선명하게 그려진다.

---

## 설치 — 파일 하나

```bash
./TokenWidget          # 또는 파일 관리자에서 더블클릭
```

`dist/TokenWidget` **파일 하나만** 있으면 된다. 파이썬·패키지·sudo 가 필요 없다
(파이썬, Tk, Pillow, 상단 표시줄 D-Bus 모듈이 전부 실행파일 안에 들어 있다).

처음 실행하면 알아서:

1. `~/.local/bin/TokenWidget` 에 설치하고
2. 앱 목록에 **Token Widget** 으로 등록하고(아이콘 포함)
3. **로그인 시 자동 실행**을 켠 다음(설정에서 끌 수 있음)
4. 설치본으로 바로 띄운다 — 상단 표시줄에 잔여량이 뜨고 창이 열린다.

다른 PC 로 옮길 때도 이 파일 하나만 복사해서 실행하면 된다. 새 버전 파일을 실행하면 설치본을
교체하고, 떠 있던 옛 버전은 알아서 꺼진다.

| 동작 | 결과 |
|---|---|
| 앱 목록/독에서 **Token Widget** 클릭 | 떠 있으면 그 창을 연다(두 개가 뜨지 않는다) |
| `TokenWidget --background` | 창 없이 상단 표시줄에만(로그인 자동 실행이 이걸 쓴다) |
| `TokenWidget --uninstall` | 설치본·앱 등록·자동 실행을 모두 지운다(설정 파일은 남김) |

독에 고정하려면 앱 목록에서 **Token Widget** → 우클릭 → **Add to Favorites**.

## 쓰는 법

### 상단 표시줄

| 동작 | 결과 |
|---|---|
| 클릭 | 메뉴: 창별 잔량·충전까지 남은 시간 / 창 열기 / 지금 새로고침 / 설정 / 종료 |
| 가운데(휠) 클릭 | 즉시 새로고침 |
| 더블클릭 | 창 열기 |

갱신 중에는 배터리 왼쪽에서 원호가 돈다.

**어느 한도를 보여줄지**는 설정에서 고른다 — **5시간**(기본) / **주간** / **낮은 쪽**(가장 먼저 바닥나는 창).

### 창

| 동작 | 결과 |
|---|---|
| `↻` · 가운데 클릭 · `F5` / `Ctrl+R` | 새로고침 |
| `···` · 우클릭 | 메뉴: **지금 새로고침** / **설정…** / **Token Widget 종료** (바깥을 누르거나 `Esc` 면 닫힘) |
| `Ctrl+,` | 설정 창 |
| 드래그 | 이동(위치 저장, 모니터 구성이 바뀌면 화면 안으로 당김) |
| `+` / `-` | 크기 |
| `Esc` · 창의 X | 창 닫기 — **종료 아님**, 상단 표시줄에 계속 남는다 |
| 메뉴 → **종료** · `Ctrl+Q` · 표시줄 메뉴 → **종료** | 진짜 종료 |

상단 표시줄을 띄울 수 없는 환경(표시줄 확장이 없는 데스크톱)에서는 창이 항상 보이고, 창을 닫으면 종료된다.

### 설정 (`···` → 설정… · `Ctrl+,` · 표시줄 메뉴 → 설정…)

맥의 설정 창처럼 **따로 뜨는 창**이고, 바꾸는 즉시 적용·저장된다(적용 버튼 없음). 창의 X 또는 `Esc` 로 닫는다.

| 항목 | 기본값 | 설명 |
|---|---|---|
| 상단 표시줄에 보일 한도 | 5시간 | 5시간 / 주간 / 낮은 쪽 |
| 자동 새로고침 · 간격 | 켜짐 · 10분 | 1분~24시간 |
| 질문하면 바로 반영 | 켜짐 | 세션 로그가 바뀌면(=Claude/Codex 와 뭔가 주고받으면) 8초쯤 잠잠해진 뒤 한 번 갱신. 45초 안에 이미 확인했으면 건너뜀 |
| 로그인 시 자동 실행 | 켜짐(실행파일) | `~/.config/autostart/tokenwidget.desktop` |
| 크기 | 100% | 80%~200% |

설정은 `~/.ccusage_widget.json` 에 저장된다.

로그 감시는 **파일 수정시각만** 보므로 토큰을 쓰지 않는다. "질문하면 바로 반영"을 켜두면 값은
거의 항상 최신이라, 주기 갱신은 길게 잡아도 된다.

## 어디서 가져오는 값인가

한도·잔량은 전부 **실측 API**, 모델별 비중만 **로컬 로그**다.

| 항목 | 방법 | 비용 |
|---|---|---|
| Claude 잔량 | `~/.claude/.credentials.json` 의 OAuth 토큰으로 `/v1/messages` 에 `max_tokens=1` 요청을 보내고 응답 헤더 `anthropic-ratelimit-unified-*` 를 읽음 | **1회 ≈ 23토큰** (haiku) |
| Codex 잔량 | `~/.codex/auth.json` 토큰으로 `chatgpt.com/backend-api/wham/usage` GET | **무료** |
| 모델별 비중 | `~/.claude/projects`, `~/.codex/sessions` 세션 로그(JSONL)를 창 시작 시각 이후만 읽음 | **무료** |

**어떤 창이 뜨는지는 계정에 따라 자동으로 정해진다.**

- **Claude**: 응답에 온 창만 — `5h`(5시간) / `7d`(주간) / `overage`(월 지출한도, 회사 계정).
- **Codex**: 요금제의 `primary_window`(보통 5시간)와 `secondary_window`(보통 주간)를 둘 다,
  크레딧 한도(`spend_control`)가 있으면 "월 크레딧"도. 창 이름은 길이로 판정(≥20일 월간 / ≥2일 주간 / 그 외 N시간).
- **이 PC 에서 안 쓰는 서비스는 숨긴다**(`~/.claude` 나 `~/.codex` 폴더가 없으면).
  `CLAUDE_CONFIG_DIR`, `CODEX_HOME` 을 쓰면 그 위치를 따른다.

각 창의 시작 시각은 `리셋 시각 − 창 길이` 로 계산해서, 모델별 비중도 **그 창 안의 사용분**만 센다.
모델마다 한도를 깎는 무게가 달라(opus > sonnet > haiku) 토큰 수가 아니라 가중치를 곱해 비중을 낸다.
카드의 `opus 5.5 40% · opus 5 7%` 는 창 전체 대비 몫이라 합이 사용한 %(=100−잔량)와 같다.

## 사내망 · 프록시

아무것도 설정하지 않아도 다음 순서로 찾아서 **되는 경로를 쓰고, 기억했다가 다음엔 그것부터** 쓴다.
프록시가 안 되면 직접 연결로 넘어가므로, 회사 밖으로 노트북을 들고 나가도 그대로 동작한다.

1. 설정 파일의 `"proxy"` (직접 지정할 때만: `~/.ccusage_widget.json` 에 `"proxy": "http://host:port"`)
2. 환경변수 `HTTPS_PROXY` / `ALL_PROXY` / `HTTP_PROXY`
3. `~/.claude/settings.json` 의 `"env"` 에 적힌 프록시 — Claude Code 를 사내망에서 쓰는 사람은 보통 여기 있다
4. GNOME 설정 → 네트워크 → 프록시(수동)
5. 직접 연결

**SSL 검사(사내 인증서)**: 시스템 인증서 저장소(배포판별 경로를 모두 확인)와
`NODE_EXTRA_CA_CERTS`(Claude Code 가 쓰는 값, 환경변수 또는 `~/.claude/settings.json`)를 함께 믿는다.
Windows 는 OS 인증서 저장소를 쓴다(truststore).

## 값이 안 나올 때

화면에 **무엇이 문제인지와 어떻게 하면 되는지**가 같이 나온다.

| 표시 | 해결 |
|---|---|
| `로그인이 필요합니다` / `로그인이 만료됐습니다` (Claude) | 터미널에서 `claude` 를 한 번 실행 |
| `로그인이 필요합니다` / `로그인이 만료됐습니다` (Codex) | 터미널에서 `codex login` |
| `API 키 로그인은 사용량을 볼 수 없습니다` | `codex login` 으로 ChatGPT 계정 로그인 |
| `네트워크에 연결할 수 없습니다` | 위 "사내망 · 프록시" 참고. 최후수단은 설정 파일의 `"proxy"` |
| `인증서를 확인할 수 없습니다` | 회사 루트 인증서를 시스템에 설치(`update-ca-certificates`)하거나 `NODE_EXTRA_CA_CERTS` 지정 |
| `사용률 정보를 받지 못했습니다` | `python3 probe_claude_headers.py` 로 헤더 덤프 확인 |
| 모델 줄이 없음 | 그 창 안에 로컬 로그가 없음 — 다른 PC 에서 쓴 사용량은 비중을 못 낸다(잔량은 정확) |

## 빌드

```bash
./build.sh
```

필요한 건 **python3(tkinter 포함) + PyPI 접속**뿐이다. 없으면 `python3-tk` 만 알아서 설치한다(sudo).

1. 프록시·사내 인증서를 위 순서대로 찾아 pip/uv 에 넘긴다(`sudo apt` 에도 프록시를 넘김)
2. 배포판 파이썬(Tk 8.6)으로 가상환경을 만들어 PyInstaller · Pillow · jeepney 설치 (`uv` 가 있으면 uv)
3. `dist/TokenWidget` 빌드 — 이 파일 하나가 배포본이다
4. 실행 = 설치(위 "설치" 참고). 떠 있던 옛 버전은 새 버전이 정리한다

오래된 배포판에서 빌드할수록 더 많은 PC 에서 돈다(glibc). Ubuntu 20.04 에서 빌드하면 20.04 이후 버전에서 모두 동작.
Windows 는 `build.bat` (결과: `dist\TokenWidget.exe`, 트레이는 pystray).

### 소스로 실행

```bash
python3 ccusage_widget.py          # Windows: ccusage_widget.pyw 더블클릭
```

필요한 패키지(Pillow ≥ 8.2, 리눅스는 jeepney / Windows 는 pystray)가 없으면 **처음 실행할 때 알아서 받는다** —
시스템 파이썬은 건드리지 않고 `~/.cache/tokenwidget/` 에만 넣는다(sudo 불필요, 프록시·사내 인증서 동일하게 처리).
Ubuntu 20.04 기본 Pillow(7.0)는 너무 오래돼서 새로 받는다.

## 손댈 만한 설정 (소스 상단)

| 이름 | 기본값 | 설명 |
|---|---|---|
| `DEFAULT_INTERVAL_MIN` | `10` | 주기 갱신 기본값(분). 설정에서 바꾸면 그 값이 저장되어 우선한다 |
| `ACTIVITY_QUIET_SEC` / `ACTIVITY_COOLDOWN_SEC` | `8` / `45` | 질문 후 갱신까지 기다리는 시간 / 최소 간격 |
| `API_MODEL` | `claude-haiku-4-5` | 헤더만 필요하므로 가장 싼 모델 |
| `GREEN` / `ORANGE` / `RED` | 애플 시스템 색 | 잔량 구간 색 |
| `MODEL_WEIGHT` | 표 참고 | 모델별 비중 계산 가중치(상대비만 의미 있음) |
| `VERIFY_SSL` | `True` | 인증서를 끝내 못 맞출 때만 `False` |

| 파일 | 역할 |
|---|---|
| `ccusage_widget.py` | 위젯 본체 |
| `sni_tray.py` | 리눅스 상단 표시줄 아이콘(D-Bus StatusNotifierItem 을 순수 파이썬으로 구현 — gi/AppIndicator 불필요) |
| `ccusage_widget.pyw` | Windows 무콘솔 실행 입구(본체를 불러올 뿐) |
| `probe_claude_headers.py` | Claude 응답 헤더 전체를 파일로 덤프하는 진단용 |
| `build.sh` / `build.bat` | 빌드 → 실행(=설치)까지 한 번에 |
